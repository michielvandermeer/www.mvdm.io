01

Uptime and DNS, checked every minute

Every configured service URL is polled every minute for availability and response time. Only state changes are recorded, so a service that stays up for a month costs you one row, not forty-three thousand.

  • On a transition from up to down, Health Check waits 10 seconds and re-checks before recording the failure or notifying anyone — this filters out transient blips
  • Every minute, each service's host is also resolved for CNAME, A, and AAAA records, following CNAME chains to their terminal records, with the full snapshot kept historically
  • You get an email the moment a service goes down or recovers, and — if you opt in — when its DNS resolution starts or stops succeeding
02

SSL certificates, graded, not just present

A daily check inspects each service's certificate directly and submits the domain to SSL Labs for a full configuration analysis.

  • You're notified by email when a certificate is missing, already expired, or expiring within 14 days
  • SSL Labs' grade (A+ through F) is stored and shown alongside each service, so a weak TLS configuration doesn't hide behind a green "up" indicator
  • Both checks run daily and independently of the minute-by-minute uptime poll, so a slow certificate scan never delays an outage alert
03

A real browser crawls your app for you

Smoke tests run a headless Chromium browser against your application, following links the way a user would, and can fill in and submit forms to reach authenticated pages.

  • Every crawled page records its status code, load time, console errors, and a screenshot — up to 500 pages per run, 10 hops deep
  • Configure input values once and the crawler drives login and multi-step forms on every run after that, chaining from one form to the next
  • Trigger a run from the UI or from a webhook, so a deploy pipeline can smoke-test a release before it's called done
  • A run's outcome is Passed, Issues (warnings or 4xx pages), or Failed (console errors, exceptions, or 5xx) — never buried in a raw error count
04

Custom telemetry, weekly digests, public status

Health Check reports on more than uptime, and shares it with the people who need to see it.

  • Install the mvdmio.HealthCheck.Client NuGet package in a monitored app to expose a /status endpoint and report custom metrics — database size, record counts, or anything else you define
  • Every Monday, an email summarizes availability and SSL Labs results across each of your projects, so you stay informed without logging in
  • Each project can publish a public status page showing availability, SSL grades, and 90-day uptime history, for sharing with your own users
