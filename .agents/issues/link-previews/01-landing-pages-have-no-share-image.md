# Landing pages have no share image

Category: enhancement
Status: ready-for-agent
Spec: .agents/specs/share-cards.md

## What was reported

Posting a link to `https://mvdm.io/products/compliance/` on LinkedIn shows only
the page title and a bit of text. There is no image. It should look much better.

## What we found

The report is confirmed. We fetched the live page the way LinkedIn's crawler
does:

```
curl -sS -A "LinkedInBot/1.0" https://mvdm.io/products/compliance/
```

The `<head>` it returns carries no Open Graph tags and no Twitter Card tags —
no `og:image`, `og:title`, `og:description`, `og:url`, `og:type`, and no
`twitter:card`. With nothing to read, LinkedIn falls back to the `<title>` and
the `<meta name="description">`, which is exactly what the reporter sees.

This is not specific to the Compliance Landing page. No page on the site has
these tags:

```
grep -rl 'og:\|twitter:' --include='*.html' .    # no matches
```

There is also no image to point at. `assets/images/` holds post images, Resume
images and four Product images, but nothing sized for a link preview. Those
four Product images are not used by any page, and there is none for
Compliance. LinkedIn wants a wide image. 1200 by 627 pixels is the common
choice.

Two facts shape the solution:

- The site has no build step for its pages. GitHub Pages serves the repository
  exactly as committed.
- The deploy workflow already runs headless Chromium, to render the Legal pages
  to PDF. So rendering images at deploy time is possible without adding a new
  kind of tool to the repository.

## Why this is parked

The metadata is straightforward. The picture is not. Nobody has decided what
the card should show, and the route to making it is a real fork with lasting
cost either way. Both are the maintainer's calls, so this waits for a
`/grill-with-docs` session.
